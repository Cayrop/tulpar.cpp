# EXP-002 Blockers & Known Issues

## Blocker B0-1: Stale Production PIDFILE at Phase Start
- **Description**: ops/run/llama-server.pid contained PID 144016 (dead) while actual V3 production server ran at PID 2052535.
- **Impact**: prod_stop.sh would remove stale pidfile and exit 0 without stopping actual server; subsequent prod_start.sh would attempt to start second server on port 8080.
- **Resolution**: ALLOW_CAPTURE_CURRENT_PROD_PID=YES ./ops/bin/prod_capture_pid.sh repaired pidfile to PID 2052535. Production stop/start then worked correctly.
- **Category**: Operational tooling bug (stale pidfile not cleaned by prior stop).

## Blocker B0-2: Expected Size Mismatch in Task Description
- **Description**: Task specification states "Verify file exists and size matches V2 baseline (~9.83 GB)" but actual V2 file size is 10,676,423,744 B (10.68 GB decimal, 9.94 GiB).
- **Root Cause**: The ~9.83 GB figure corresponds to the V3 model file (9,828,981,664 B), not the V2 model.
- **Verification**: V2 file matches Phase-1B recorded model exactly (SHA256 46151b52..., size 10,676,423,744 B).
- **Category**: Documentation mismatch; no functional impact.

## Blocker B0-3: ON-63k High Spread (7.64%)
- **Description**: on-63k arm shows 7.64% spread (min=29.02, max=31.35) exceeding typical <1% target.
- **Root Cause**: First rep (fresh prefill, cache_prompt=False) wall time 214.68s vs typical 13s for cached reps. E2E tok/s = 1.77 on rep1 vs ~29-31 on cached reps. This inflates spread calculation which uses all reps.
- **Diagnostic**: Repeated as on-63k-r3 (5 reps) with similar pattern: rep1 29.02, reps 2-5 clustered 29.70-31.35.
- **Assessment**: NOT a correctness issue - median decode speed stable. Variability in fresh prefill performance at 63k context under current system load conditions. Does not affect measurement reliability for median.
- **Category**: Measurement noise / system variability; documented.

## Blocker B0-4: Prod Restart Required Between Ladder Arms
- **Description**: srv_ctl_v2.sh start uses `assert_no_llama_server()` which checks `pgrep -x llama-server` and refuses if ANY server is running (including production).
- **Impact**: Must stop production before each ladder session, restart after.
- **Resolution**: Expected by design (pidfile policy). Production managed via prod_stop/start, ladder via srv_ctl_v2.
- **Category**: Design constraint; no fix needed.

## Blocker B0-5: No Phase-0 SVG Artifact for Direct Comparison
- **Description**: Task section 2.3 requests "Compare with V3 output from Phase-0" but grep of entire repo found no SVG artifacts from Phase-0.
- **Impact**: Cannot perform direct V2 vs V3 SVG quality diff as specified.
- **Resolution**: V2 SVG output recorded as new baseline; V3 behavior inferred from identical prompt response pattern (identical valid SVG structure expected).
- **Category**: Missing historical artifact; documented.

## Blocker B0-6: Hardcoded Model Path in Production Scripts
- **Description**: prod_start.sh, prod_stop.sh, prod_capture_pid.sh all hardcode MODEL path (not sourced from prod_flags.env MODEL_PATH).
- **Impact**: Model swap requires editing 4 separate files (prod_flags.env + 3 scripts).
- **Resolution**: All 4 files updated during EXP-002 with .bak backups.
- **Category**: Technical debt; could be refactored to source MODEL_PATH from manifest.

## Blocker B0-7: Semantic Record "Foreign KV" Pattern in Factual Test
- **Description**: Both V2 and V3 semantic smoke for "factual" (capital of France) produce continuation containing "What is the capital of Germany?" generated by model (ignore_eos=True).
- **Assessment**: Not KV contamination - simply model generating follow-up questions with ignore_eos. Phase-0 classified this as "foreign KV echo" but in current context it's expected ignore_eos behavior.
- **Category**: Misclassification in Phase-0; no current issue.
